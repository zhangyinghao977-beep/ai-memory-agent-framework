**编纂版 2026-11-07-r1，讨论快照，非新的定案规范。** 本文汇集既有词典、后续澄清及代码中的实际含义，供读者从头阅读，不要求先读旧版增补。它不替换作者的版本号，也不把实验代码反过来当作理论定义。“完整”指覆盖本次可核资料中的主要概念和跨项目歧义，不表示所有机制已经定义完毕。

深渊是一套研究中的经验主义人工智能方案，包含记忆、知识组织、路径与学习的设计；红尘仙是一套面向黑盒 Agent 的记忆与工作协作方案。两者均为半成品研究预览。这里的术语是**项目用法**；采用一个定义、写出接口和取得实验支持，是三种不同状态。

## 怎样读本词典

每条尽量区分**作者定义／阶段共识**、**工程操作含义**及**未定事项**。英文是本次编纂译名；KA、EA、PA、CA 等未明确展开的缩写不擅自补造英文全称。正文中的 `D54:345` 指来源 D54 的原文行号，其余来源编号见文末。私人原话、聊天全文、账号及本机绝对路径不附入公开版。

来源优先级不是简单按文件末尾或修改时间排序：明确声明取代旧说法的修正优先；可运行实现只能说明它做了什么，不能改写作者的概念。最新 R26 文件连续记录三轮修正，但尾部仍留着旧结论。本文保留这段演变，**不把被撤回的尾部文字作为当前定义**。R26 是研究者整理的用户确认记录，并非本次取得完整对话后重新逐句认证；歧义仍照实保留。

## 事件链：先确定讨论的是哪一层

| 用法 | 指什么 | 不能自动推出什么 |
|---|---|---|
| 深渊的广义事件链 | 知识的组合、操作和关系的组织；以广义 AST 表达，并承接 what／why／how 之间的路径 | 不限于按时间排列的日志；不因叫 AST 就已获得完整执行语义 |
| 某次发生／执行实例 | 某次使用了哪个结构版本、绑定了什么、尝试到哪里、结果和依据是什么 | 有记录不等于事件已在现实发生；计划、观察、执行与转述须区分 |
| 路径记忆 | 具体对象与抽象概念、具体对象之间等可复用对应路径 | 不是只存一串近邻坐标，也不等于所有参数或所有聊天记录 |
| 红尘仙工作事件链 | Agent 的任务、分工、状态、反馈、资源和交接的工作组织与追溯 | 不自动继承深渊知识 AST 或九类转换的实现与验收 |
| 实验中的“链” | 由该实验生成器、张量或样本协议规定的输入 | 名称相同不意味着覆盖完整理论；须给出模型实际读取的字段 |

这些是阅读与实现的区分，不是规定五个彼此互斥的数据库。同一过程可以有可复用结构、若干发生实例和后续知识组织；它们的关联需要保留。来源：D54:343–364、477–485；D57；R26；H0；U-AST、U-COMPOSE、U-HCX。

### E01 事件链／广义抽象语法树 — Event chain / generalized abstract syntax tree

**作者定义：** 事件链原本就是对语法树的抽象，后来明确命名为广义 AST；知识组合就是事件链，链本身也是知识。它表达组成、操作及关系，能够嵌套、折叠引用、展开和连接，不只是先后发生事项的列表。这里的 AST 用法扩展到经验与操作，不要求全系统物理存成一棵普通语法树。

**操作与边界：** 当前登记核心有版本化结构、子节点及槽映射；神经实验中的短链另有各自数据格式。跨链共享、反馈、循环的算法及语义保持不能由名称保证。演变：早期语法树抽象 → 2026-10-25 明确广义 AST → 10-31 重申知识组合关系 → R26 对选择步骤作更具体的解释。来源：D54:22–28、345–364；A0；U-AST、U-COMPOSE；R26。

### E02 逻辑／可达路径 — Logic / reachable path

**作者定义：逻辑是知识的可达路径。** 路径包含一步步从当前知识、条件和参考中取得后续知识或结果的过程，不必等到长链才算路径。具体门及条件 → 抽象开启关系 → 所需钥匙关系 → 具体钥匙，是具体与抽象往返的示例。

**操作与边界：** R26 最新纠正允许把一次比较并选择读作 what→what 事件链过程。这不证明其余八类转换已经实现，也不把“选对候选”扩写成开放世界推理或整个理论得到证明。路径的定义域、约束、未知和失败均须保留。来源：D54:221–245、273–287；R26:7–26。

### E03 节点 — Node

**最新作者口径：** 在本轮理论讨论中，事件链节点指算子动作，关联 what／why／how 的转换职责；一行向量是可能的工程承载，不是定义本身。R26 第二轮纠正撤回了“T 系列没有这个意义的节点”的绝对说法：定位／比较／选取可解释成一次 what→what 过程。

**操作与差异：** 登记核心 `Node` 是带种类、槽和子节点引用的结构对象；T 系列向量行主要表示对象，不能将每一行直接认作完整算子；红尘仙记忆段落可以作为定位单元，但没有建立“每段＝每个理论算子＝每条账本事件”的恒等式。九类动作的统一编码仍未定。来源：R26:7–26；A0；U-HCX；H0。

### E04 3×3 转换／九类算子 — 3×3 transformations / nine operator roles

what、why、how 可各自转到三面，包括自身到自身；九格描述职责范围，不是固定九步流水线，也不是恰好九个已完成算法。当前核心 `record_flow` 能登记起止面、输入和输出；登记一条流转不等于执行或学得该转换。R26 只对当前比较选取给出 what→what 的对应，不能补齐其余格。来源：D54:359–364、507–525；A0；R26:20–26。

### E05 路径作为函数 — Path as function

这是项目建模要求：每一步路径应给出输入—变换—输出的函数描述；它不把每条画出的边自动变成已定义、全域或可逆的数学函数。改变参考系如同换尺子，须交代坐标／表示转换及适用范围。来源：D54:273–287。

### E06 抽象结构与实例状态 — Abstract structure and instance state

可复用结构说明位置、连接与推进关系；实例状态说明本次绑定、进度、中间产物及依赖版本。二者通过绑定相连。保持区分使多次使用不必改写同一结构，但不规定必须分成独立服务或把全部状态塞进稠密张量。冻结、保存及恢复协议仍需具体设计。来源：D54:38–81；A0。

### E07 发生记录／Occurrence — Occurrence record

工程中的一次实例登记，连接结构版本、缓存和经验／记忆依据。来源类型区分计划、已执行、观察及转述；因此接口名 `occur` 或表中有一行记录本身，不构成现实发生证明。同一结构可以有多次记录，每次绑定、时间和结果不同。发生记录也不能替代广义事件链的全部结构含义。来源：A0；D54:477–485。

### E08 主链／子链与 how 出口 — Main chain / subchain and how output

角色相对于任务范围而定：对上是子链，对自身负责的任务可为主链。子链通过约定输入、结果解释与报错协议连接；发起请求与接收反馈是不同步骤。how 出口提供约定内容，具备读取条件的其他链也可使用，不限定只供父链。局部结束不能代替上层任务完成，也不授予对外共享权限。来源：D54:118–130、453–475。

### E09 折叠／展开／半解耦 — Folding / unfolding / partial decoupling

折叠以登记的整体或引用使用内部过程；展开在需要时进入组成关系和子链。主链先按职责推进，必要时接入子链结果，保留来源与反馈联系，称为半解耦。不能把折叠理解为无痕删除失败经历，不能把读取子树当作已证明语义等价的执行。来源：D54:431–451、752–766、807–814；A0。

### E10 回溯／回滚／重放／恢复 — Backtracking / rollback / replay / recovery

回溯既包括事后查依据，也包括展开中返回选择点换路；旧尝试及反馈保留。计算状态回退、按记录重放和在中断后恢复是不同能力，分别需要证据。逻辑可逆不使已改变的现实动作自动撤销；有日志不保证恢复了原状态、身份或计算。来源：D54:102–108、768–805；H0。

### E11 循环、迭代与资源池 — Loop, iteration and resource pool

同一循环子链可以执行多轮，n 轮不等于 n 条新子链；各轮共用本次循环的有限资源预算，不无条件刷新。迭代承接旧经验与有效部分并修订组织；“循环＋迭代”强调积累延续，不是每次架构变化清空重来。有限资源下挂起保留未完成状态，不等于完成。资源计量、续拨及退出策略须另定。来源：D54:110–162；D57；U-ITER。

### E12 损失／代价／账单 — Loss / cost / accounting

既有讨论用这组词描述过程及路径的代价，主子链有关联但不共享损失。必须写清语境：这不自动等同于代码里的交叉熵训练损失，也不意味着子链没有物理耗费；红尘仙 spend／settlement 是工程账本。不要将相同词形跨理论、优化目标和资源计费直接代入。来源：D54:975–983；H0。

### E13 记忆库的两种当前语境 — Two current senses of memory store

**作者最新区分：** 一种是 Agent 系统保存工作经历的记忆库；另一种是经验主义架构工作时保留的自身映射／路径记忆，例如某把钥匙与某扇门、具体钥匙与钥匙概念、具体门与门概念的对应。路径记忆也是知识的一部分。两者可关联，不能只因同名就宣称互相实现。

**实验边界：** R26 把 T13 放在前一种方向；后续 T13 草稿又提出了冻结权重的 FSM 路径记忆组，方法尚未定。所检查的 T13 目录仅见未冻结草稿，未见实现或运行回执，不能把新增分组写成成果。T 系列当前对象向量及比较器未完整实现后一种具体—抽象路径记忆。来源：R26:7–16；D54:213–245；T13:72–78。

### E14 学习、训练与“胚胎阶段” — Learning, training and the “embryonic stage”

**最新限定定义：** R26 第三轮将系统启动后以简单 FSM 记录到记忆库的过程称为这里讨论的人类意义上的“学习”；梯度训练归入系统形成前的初始化／“胚胎阶段”。这是本项目本轮采用的分期术语，不是对机器学习或人类生物学的一般定义。

**演变与操作：** 它取代了第二轮“不重启也能挂入记忆”及“训练是否算重启”的分法。旧词典的“学习层／学习森林”仍指组织、抽象与修订职责，不能据新分期删掉其机制。T12 的梯度更新应明确写为训练；`sim` 重算表示也不直接等同于简单 FSM 记忆写入。T13 只有方案时不能写成已经实现学习。FSM 的最小动作、启动边界及与训练组织的完整接口仍待定。来源：R26:35–57；D54:527–609、840–863。

### E15 抹平 — Flattening (project sense)

指作者所说“不区分知识本身的信息”而把它压入向量表示的情形；它不是“只要用了向量”或“旧题掉分”的同义词。R26 第二轮撤回了仅因 T 系列使用向量就指认其抹平的解释。T12 没有直接量化这个概念；不能据下降或向量邻近证明发生／未发生抹平。如何检测身份、信息及路径区别是否保留仍待定义。来源：R26:7–26、59–69。

### E16 结晶／晶格／热力学与熵损失 — Crystallization / lattice / thermodynamics and entropy loss

“结晶”描述知识从经验关系中逐步汇聚的设计方向；“晶格”在各实验中又具体指不同的表示和约束，见实现对照。作者近期把链变化中的损失与热力学联系，指向的是事件链本身。本文保留这一理论动机，但没有据此建立物理熵、概率空间、状态方程或守恒关系，也不能将训练 loss、能耗和熵直接等同。

R26 的纠正说明结晶意图不是凭空给知识，不构成现有实现已保存全部知识信息的测量。热力学对应和“抹平”的验证均开放。来源：R26:20–26；U-ENTROPY；E26。

### E17 “基于我们的构造”与 EA／CA／PA 边界 — “Based on our construction” and scope labels

R26 允许将当前相关小模型称为“基于我们的构造”，但限定到 EA／语句级别，不能写为完整架构。语句级是本次对应说明，不证明每句话只有一个节点或一条链。CA 出现在该讨论中，尚未找到足以确定其完整含义、英文展开及与 PA 是否同义的明示定义；保持待确认，不擅自合并。来源：R26:15–16；U-KA。

### E18 路径受影响／知识丢失 — Path interference / loss of knowledge

旧任务掉分是观测指标；路径暂时不可达、读出器与新坐标不匹配、信息真的被覆盖、后续快速再学习，是不同解释。即使换坐标后下降或旧题再次训练后恢复，也不能单独排除这些替代解释。概念相容不等于正面实验证据；新定义不追改已冻结预测及原始成绩。来源：E26；R26；D54:768–805。

## 本轮修正如何承接旧说法

| 议题 | 旧解释／歧义 | 当前编纂处理 | 尚未解决 |
|---|---|---|---|
| 事件链 | 只当时间日志或固定语言树 | 广义 AST／知识组合，另记具体发生 | 通用执行语义与训练编码 |
| 节点 | “T 系列没有节点” | 撤回绝对说法；比较选取可作 what→what 过程 | 其余转换与统一节点表示 |
| 首成员／知识包 | 没有显式首成员就不能称包 | 概念首成员与显式实现分开；允许带限定称知识包 | 是否形成可索引的包对象与固定参考 |
| 抹平 | 因表示为向量或掉分而认定 | 不以这两点作判据；R26 第二轮优先 | 可检验的信息保留标准 |
| 学习 | 不重启／能继续训练即学习 | 第三轮以启动后 FSM 记忆写入限定；训练单列 | 启动边界及与旧学习层术语的完整衔接 |
| 红尘仙事件链 | 把深渊 AST 验收直接搬过来 | 按 Agent 工作链与实际工程单独说明 | 完整分支协作、原身份恢复与长期实验 |

R26 尾部还写着“没有节点／首成员”“可能被抹平”“学习待确认”，与其前面声明优先的第二、三轮纠正冲突。本文按明确的修正顺序整理，不改动该历史源文件，也不称本词典已经结束全部讨论。

## 核心概念与机制

以下 C01–C41 承接既有词典的主要分类。当前 R26 修正优先于与之冲突的历史表述；未被修正的机制职责继续保留。

### C01 三疑问面：what／why／how

作者定义。what 指知识及组织，why 指连接计算和广义函数映射，how 指实践、工具及过程组织。同一对象可在不同面之间转换，三者不是永久隔离的模块。工程上必须写明每次转换的输入、操作、输出和反馈；三面划分尚不是对全部计算的完备性证明。〔D54:165–184,96–100〕

### C02 知识、记忆知识与抽象知识

作者定义，v0.53 分类。知识包括记忆知识与抽象知识；记忆知识再分长期记忆知识与缓存记忆知识。抽象知识强调可复用的组合及关系；长期保存本身不构成抽象，登记存在也不构成验证。分类依据是内容职责，不是磁盘／内存或持久／易失的划分。〔D54:84–90,175–180〕

### C03 经验

作者定义。经验是实践、观察、对话或语料带来的经历与材料。D54 的形成方向要求经过拆解学习，而不是将输入原封不动视作已形成的知识。工程上保留来源、条件及材料性质；收到一个说法、作出一个推导、实际执行并取得反馈须分别记录。原文留存不能证明其内容为真。〔D54:175,184,713,740–750〕

### C04 记忆与记忆层

作者定义。记忆组织具体经历、关系、条件、组成及时间／版本，不能只剩最后答案。记忆层在功能上独立说明，但不要求单独物理数据库。既有依据与后续解释分开：外部可引用记忆，后来的可变解释不能反向改写原记忆的当时含义。不可篡改不等于不可遗忘，保留范围仍须明确。〔D54:174–176,717–734〕

### C05 长期记忆、缓存记忆与串联缓存

作者定义加工程候选。未完成子链、进度、中间产物及受阻尝试可以属于缓存记忆知识；缓存不是记忆的反义词。长期与缓存的转换、期限及淘汰机制未定。共享结构与实例状态分离、保存一致状态后释放活动资源是候选接法；有记录不等于任务完成、无限保留或可无损恢复。〔D54:24–81,84–90,126–134〕

### C06 具体知识库、抽象知识库与中间绑定区

作者的项目约定。某部分属于自我范围，与当前能否完全掌握它，是两个问题；作者用“自我缺失”讨论整合或自主控制受限的状态。英文建议用 incomplete self-integration 并保留项目限定，避免被误读成通用医学术语。量表、阈值和可观察判据未定，局部自主不自动排除组成归属，也不能据此给人或人格分级。〔D54:901–916,928–944〕

### C39 时空可回溯、联合恢复与确定性重放

作者原则加工程区分。优化需保留身份、版本、来源、绑定及依赖，说明当时用了什么依据；“空间”先指结构位置和关联范围。可追溯解释、恢复相容的联合状态、按指定一致性重放是三项能力，各需证据。日志存在不保证恢复或逐位重现；缺失依据不由当前状态补造。影响结果的依赖变化，应将相关旧结果标记待复查或失效；具体检查点、失效和保存策略待实现。〔D54:768–805〕

### C40 验收状态与证据层级

D54 的编写约定。类比／启发给方向；工作假设／候选待检验；工作定义／阶段共识说明已采用的概念；特例成立只覆盖所述约束；经验验证限定数据和条件；数学保证需要前提与证明。已实现、已运行、已通过分别需要源码、运行记录和验收证据。未知／未找到不等于不存在。NOT_RUN 与 REVIEW 不应改写成成功，设计状态不能因术语登记而升级。〔D54:9–16,946–957〕

### C41 传统派／函数派及表示名词的限定

项目内命名。D54 的“传统派／函数派”均指讨论中的传统 Transformer，不是两个公认流派。D54 没有给“格点”或“硬边界”独立完整算法定义；具体实现中的对象向量行、成员槽、标量评分槽与语义 slot 必须分别标注。缺失语法边不自动构成禁止未知关系的硬掩码；晶格、势与熵的后续理论表述及实验对应应在版本专节说明，不能回填成 D54 已定义／已测。〔D54:186–191,367–391,410–415；D57:31〕

## 实现、协议与实验中的术语

本节描述本仓库公开代码及已归档实验的具体用法，不把接口存在写成算法已完成。概念依据、代码操作和验证结果是三层证据：设计说明概念，源码说明当前契约，运行记录才说明该版本在指定条件下实际做过什么。旧源码注释可能描述较早状态；例如已有 `learning_store.py`，不能仅凭其他模块中的旧注释继续称其全部未实现，但其登记接口也不等于自动学习算法。[设计边界][A11]、[实现证据][A12]分别限定这些层次。
