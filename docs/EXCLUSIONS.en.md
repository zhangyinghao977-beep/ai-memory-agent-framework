# Candidate scope and scanning limits

[简体中文](EXCLUSIONS.md)

The Hongchenxian section contains thirty-two `.mjs` files selected from one sealed candidate, with preview documentation and verification scripts added. The Abyss retains four Chinese/English pairs of technical summaries and now includes selected research source from the original local working tree in [implementation](../projects/the-abyss/implementation/): 65 core `.py` files, 25 `test_*.py` files, 31 experiment `.py` files (including helpers), and 11 plan configurations for fresh runs. The original working directory was not copied wholesale.

Relative source names and hashes at inspection are recorded in [SOURCE_SNAPSHOT.json](../projects/the-abyss/implementation/historical/SOURCE_SNAPSHOT.json). The candidate includes separately documented portability edits. Fresh-run configurations are not historical frozen records, and historical summaries are neither raw receipts nor independent replications. This preparation did not modify the original research working tree or running experiments; see the [provenance and evidence notice](../projects/the-abyss/implementation/NOTICES.md).

Excluded: the official plugin/launchers and original Python runner from the Hongchenxian environment; raw public-source excerpts; server configuration and readouts; historical transfer scripts/tar/b64 packages; account directories; real databases/WAL/SHM; real member memory; original model replies; email/chat records; personal information; private links. The full glossary containing private discussions, private collaboration records, and historical originals with private paths are also excluded.

The Abyss additionally excludes external-material adapters, the retired toy task, third-party corpora/lexicons/tokenizer artifacts, token shards, pretrained weights, runtime databases, and original run receipts. T1–T10 generate synthetic inputs and do not require those external materials. Only provenance and acquisition guidance are retained for third-party materials. Public acquisition, exact provenance versions, and licensing for the 119M backbone remain unresolved, as does a complete procedure to rebuild `corpus_index.sqlite` from Parquet; see [data sources](../projects/the-abyss/implementation/docs/DATA_SOURCES.en.md). A [public license for the project code has not been selected](../projects/the-abyss/implementation/LICENSE-STATUS.md).

The candidate scan checks common secret formats, private paths, account/host identifiers, email, IP addresses, sensitive file types, symlinks, and static import closure. It reports only locations/categories, never matched values. A precise reviewed exception covers intentionally fake header values in synthetic tests; unknown values remain findings.

Scan conclusions are limited to the corresponding script's coverage and actual reports. The scan is heuristic and cannot prove the absence of every secret or third-party rights issue. Hashes check file bytes against an inventory; they do not establish code security, authorship rights, or the version used in historical experiments. The scan does not read parent directories, original credential directories, or real datasets.

No dependency installation, pytest run, training, or download was performed while preparing The Abyss source. Historical results do not validate this new copy. Later additions or changes require scanning and verification appropriate to their scope and an updated inventory.
