# FSM：当前状态、未来接续与事件链

[English](FSM_CONTINUITY.en.md) · [词典](GLOSSARY.md) · [架构流程](ARCHITECTURE_FLOWS.md)

更新：2026-11-10。新增 U-FSM-1110：后续接管与登记边界；原来源 U-FSM-1109：项目作者与助手本轮讨论中的明确确认，以下为技术转述。本文记录设计定义，不表示实现完成、测试通过或当前 AI 已具备主观体验；不改写历史实验。

## 1. 分工与整体联系

**记忆属于过去，逻辑属于现在，FSM 属于未来。** 这是项目的职责分类，不是三个互不相干的盒子。逻辑、记忆和 FSM 必须在运行中保持实际联系；工程可分模块推进，局部实验不能代替完整系统验证。

逻辑是“大脑”，FSM 是“身体／工具”。FSM 不承担理解任务、关联经历和决定目标的逻辑判断，但能够执行纯符号判断，包括 if/else、阈值比较、明确规则和状态转换。不能把“不理解”误写成“不能判断任何条件”。资源变化与哪项任务有关、是否继续某项工作，由逻辑结合记忆判断，不要求 FSM 自己知道。

FSM 不只有未来接续的作用，也必须与当前物理状态、资源池和存活情况相联系。这不改变其“属于未来”的分类，也不把当前理解职责从逻辑转给 FSM。

## 2. 资源保护的条件与余量

资源池对应实际物理／计算资源。资源保护的具体条件可以随经验调整，但不能突破物理限制。不得把可调整的保护条件误写成真实容量也能随意改变。

默认资源保护需要预留登记记忆的余量，避免等到耗尽才处理；特定逻辑接管的例外见第 6 节。既有固定协议中的“先保存记忆，再报告”继续保留。预留多少、怎么测量及如何验证保护有效，本轮未指定固定值。

普通波动不必逐次打扰逻辑。当前分配好的工作部分未超出预设范围，可以不管；超出范围则需要关注。这里的“不管”不等于删除记忆或关闭必要的状态查看，也不代表所有任务使用相同阈值。

## 3. 异常的符号侧分流

- **低危：先报告，交由逻辑决定。** 报告后的步骤按具体情况继续或暂停，不一刀切；具体风险扩大判据仍需设计与验证。
- **高危：直接拉闸，再报告。** 对明确需要终止的问题，例如已明确的内存泄漏，FSM 可以依据规则自行终止，无须先让逻辑理解原因。

风险分流可以由符号侧按明确条件判定；并非每次超出预设范围都立即终止，也并非所有异常都等待逻辑处理。以上不构成已实现的泄漏检测算法。

后续已明确：默认高危处理是**中断当前执行任务，保存完整记忆，再报告并唤醒逻辑**；逻辑在睡眠或暂未运行时也直接唤醒，不等自然醒。完整记忆包含原因、进展、过程和上下文，不只是简短标记；不是默认关闭整个进程或整机。

FSM 保存原始记录并按固定规则登记时间、结果、当前事件链等基本项。**索引和简介由逻辑确定**，FSM 不自行理解内容生成它们。逻辑随后处理记录、索引、简介及后续决定。“先保存再报告”是默认协议；实际故障条件下的完整性、持久化和可恢复性仍需工程验证。

## 4. 事件链分步与未完成任务

要对当前工作部分的范围进行检查，需要事件链那样将一个任务拆成 n 个步骤的能力，否则整个任务可能堵在一起。这里不规定固定 n、固定步骤粒度或全局统一预算。

缓存和记忆可以登记做到一半的任务，保留已经发生的过程与进度，为后续接续提供依据。是否恢复、怎样调整由逻辑判断。保存未完成任务不等于 FSM 必须理解其意义，也不意味着资源恢复后强制自动继续。

**学习事件链是工作事件链的子集，经验派与 agent 切片使用的是同一个事件链概念。** 详见[后续事件链澄清](EVENT_CHAIN_RELATIONS.md)。 agent 方案的事件链不需要承担该学习整合，因为它无法整合进现有逻辑层；经验派则把事件链纳入完整学习架构。应区分覆盖与整合范围，不把两者割裂为互不相干的概念，也不据此宣称两边实现相同或切片已实现完整学习。

## 5. 模型、agent 与完整架构的递进关系

以下是作者在项目内的分类，不是通行学派分类：

1. 严格传统派：基于 Transformer 的 LLM 本体。
2. 改良派／广义传统派：基于这类 LLM 的 agent 框架。
3. 妥协派：在上述 agent 框架上加入本项目的记忆库与 FSM。
4. 经验派：重新构建自带记忆库与 FSM 的完整人工智能架构。

最初直接从传统派构想经验派，中间层次被折叠；因完整实现困难，后来切出妥协派，与改良派比较。妥协派是切片，不是最初的最终目标，也不是完整经验派已经实现的证据。比较必须区分模型本体、外接框架和完整系统。

## 6. 在途调整与特定逻辑接管

一般预算或条件调整应考虑已投入资源和当前进展，不能因规则变化就统一取消在途任务。默认高危保护则直接执行，不等逻辑权衡；反射只是解释类比，不是生物学等价或实现证明。

作者同时保留**特定情境下由逻辑直接接管、承担危险并强行执行**的例外。逻辑可以投入包括登记记忆余量在内的可动用资源，承担完整记录无法留下的风险，但不能突破客观物理容量。这是项目设计讨论，不是现实部署中绕过外部权限、安全约束或授权边界的许可。

关于接管结束，作者使用“资源池耗尽＋逻辑放弃”，并明确“＋”表示同时，而非任一条件。事件是否结束由逻辑判断，不规定某一步结束即自动交还。实际资源耗尽时逻辑如何仍能判断或执行，是尚未验证的工程问题，不能把这段定义视为已运行的停机协议。

**临时大记忆库是待实验假设。** 逻辑接管时可以暂不考虑其他可能，把算力和存储集中到当前任务某一局部能力上，尝试把可用代价换成执行资源。作者明确目前没有真正实验验证该设想；不能写成已有性能优势或保证完成任务。

## 7. 继续讨论的具体事项

基本职责、符号判断、范围检查、高危中断当前任务并完整登记和唤醒、索引简介由逻辑确定，以及低危按情况处理，均已确认，不再整项列为未定义。

仍需落实：各步骤的具体范围和风险条件；可靠识别内存泄漏等问题的方法；登记余量的测量；低危分流的具体符号规则；缓存、原始记录及逻辑补全的接口；条件修改对在途动作的精确适用机制；特定接管与资源耗尽的可运行语义；临时大记忆库的实际实验。原始事实、失败和历史成绩不被这些新定义覆盖。
