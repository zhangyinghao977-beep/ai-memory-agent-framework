# 逻辑记忆与 FSM 的设计原则和评价方法

[仓库入口](../README.md) · [深渊设计](../projects/the-abyss/DESIGN.md) · [红尘仙架构](../projects/hongchenxian/docs/ARCHITECTURE.md) · [术语汇编](GLOSSARY.md)

记录日期：2026-11-07。本文整理项目作者本轮明确的设计原则，并对照公开仓库的实际代码与既有证据。它是一份当前讨论整理，不代替全部架构规范，也不新增学习实验结论。

**核心原则是：保留记忆原文，组织和使用知识关系，以局部注意力按需展开相关材料；以准确、可靠、不被随意污染、速度和诚实保留未知来检查系统的具体差异。** Agent 方案借用底层模型已有的知识关系能力，是经验主义方案的一种工程切片。切片的通过结果不能代替完整架构的验证。

本文区分三种状态：**设计原则**说明系统应怎样工作；**已见实现**说明公开代码具体提供什么；**待验证事项**说明仍需要什么证据。作者的理论解释不会因被整理成文就变成实证事实，源码存在也不等于行为已经通过验证。

## 一 逻辑 记忆与 FSM 怎样分工

项目的核心命题是“逻辑是知识的可达路径”。从这一命题出发，本轮以逻辑、记忆和 FSM 说明完整方案的基本职责：

- **逻辑**组织并使用知识之间的可达路径，在当前条件下定位、比较、组合、展开和判断。路径成立需要明确输入、适用条件、转换与输出，不能只由名称或连线保证。
- **记忆**保留具体经历及其原始记录，让之后的工作可以回到来源，重新读取、区分和解释，而不是只依赖一次概括留下的印象。源内容、登记版本、来源类型和适用情境需要分开标记。
- **FSM**承接活动触发和状态转换，使写入、调用、等待、接续等过程有可追踪的状态。既有讨论还提出可依据经验修正映射，但最小动作、可修订范围及完整接口仍待明确。

这是一种职责划分，并不要求恰好三个独立程序，也不把全部逻辑缩成一个固定状态表。既有词典将启动后的简单 FSM 记忆记录过程称为本轮语境中的“学习”，将梯度训练另列为初始化／“胚胎阶段”；这是项目限定的分期用法，不改写机器学习的一般术语。它也不取消旧设计中的知识组织、抽象和修订职责。

红尘仙的工作链记录任务、工具、依赖、回执与恢复，深渊的广义事件链研究知识组合、操作和关系。二者可讨论映射，但协作账本、固定 FSM 和完整知识学习不能因术语相近就视为同一实现。详见[术语 E01、E13、E14 与 C36](GLOSSARY.md)。

## 二 记忆原文和知识关系要分别讨论

### 记忆原文保留

**作者本轮明确的原则：记忆原文不压缩；可被压缩的是知识关系，例如 KA、EA、CA 所涉及的关系组织与计算。** 这里的“不压缩”针对以摘要、概括或抽象表示替换原始记忆内容的做法。本轮没有另行规定磁盘编码或通用无损文件压缩格式，不能从这句话擅自推出存储格式要求。

因此，减少一次调用读取的内容、为记录建立索引、为索引编写简介、分页返回材料，都不能被解释为可以删除或改写原文。原文、关系表示、索引和简介分别承担职责；原文保留后，其他组织形式可以修订，并保留其来源与版本。

原文保留不使其中的内容自动成为事实。一次猜测、一次错误回答和一次转述都可以被准确记录，后续使用时仍须区分它们与已核实的观察。修订认识应能解释新依据如何改变当前判断，同时保留此前的记录和失败经历。

### 知识关系的压缩是作者的设计解释

KA、EA、CA 在本项目不同轨道中有局部计算职责。作者用它们说明可压缩的对象是关系，而不是所保留的记忆原文。本文不据此声称已有统一的关系压缩算法、已证明压缩无损，或已测量任意知识都能完整恢复。

**后续正式澄清（2026-11-07）：** PA（Page Attention）已改名为 CA（Chain Attention），PA 仅作为旧名保留。使用侧寻址顺序是 **CA → EA → KA**：先在链间定位核心语句并联系上下文，再定位所需 SLOT 关系，最后寻址对应知识。此顺序不规定全部学习／训练都按单趟全序执行；知识包与学习事件链的循环和相互修订仍需分别描述。此前“PA 与 CA 关系待确认”是已被本次确认取代的历史状态。更名与设计顺序不使全部 attention、参数或关系表示成为一个已验证机制，也不补造 KA／EA 的英文全称。参见[术语 E17、C21 与 I30](GLOSSARY.md)及[使用寻址图](ARCHITECTURE_FLOWS.md#use-addressing)。

## 三 Agent 方案为什么是切片

**作者的解释是：底层模型已经承载了经训练形成的知识关系能力，Agent 方案可以先借用这些能力，而把本轮重点放在记忆原文的保留、索引、读取与工作接续上。** 这样不必先在外层重做一整套 KA／EA／CA 关系学习，便能研究完整构想中的一部分功能。

“已经压缩了知识关系”在这里是作者对底层模型作用的理解，不是本次对模型内部机理取得的新证据。借用模型能力也不意味着这些能力可靠、完备、无误或可逐一解释，模型仍可能误读材料、遗漏条件或编造答案。

切片因此有两方面边界：

1. 它可以验证外层记忆与工作协议是否有效，例如原文能否找回、旧版本能否核对、来源是否匹配、中断是否保守接续。
2. 它不能仅凭这些结果证明完整经验主义架构已形成知识关系、完成可修正 FSM，或获得一般学习能力。若使用强底层模型，必须区分模型原有能力、记忆提供的事实和外层协议各自的贡献。

## 四 局部注意力怎样提供材料

这里的“局部注意力”首先是**工作时组织可见材料的策略**，不直接宣称已经实现某一种神经网络 attention 算法。

作者要的不是孤立地选出一个段落后立即作答。目标段落要与**索引相关的上下索引简介**一起提供，让系统知道它处于什么语境、附近还可能有什么材料，再按任务需要继续展开。上下关系可以涉及结构层级和关联位置，不能未经定义就全部简化成物理相邻的前后两段；具体关系字段仍需落实。

据此，工作过程可整理为以下职责顺序。它是原则的工程展开，不是声称现有代码已经自动完成每一步：

1. **定位入口。** 根据当前问题查找相关索引，记录检索方式、作用范围及版本。没有命中只说明本次入口没有找到，不直接说明记忆中不存在。
2. **取得局部语境。** 读取目标段落的原文，并提供相关上下索引的简介和可继续展开的引用。简介说明“这里可能有什么”，不是对原文的替代。
3. **判断是否需要展开。** 遇到指代不明、条件缺失、例外、冲突或简介与原文不符时，继续读取对应原文、上层背景、相关分支或历史版本，而不是根据简介补造内容。
4. **按依据形成回答。** 区分原文中的事实主张、索引编写者的解释、底层模型的一般知识以及当前推导。需要原文支持的结论不能只拿简介作最终依据。
5. **明确停止状态。** 已充分支持、仍有冲突、尚未找到、来源不可访问和预算不足应分别记录。预算耗尽是工作状态，不是证明材料不存在，也不能改写成任务已完成。

简介可以简短，也可能有遗漏或解释偏差；它承担导航成本的取舍。判断一项取舍是否有效，应检查它有没有把关键限定藏掉、能否在需要时展开、展开后是否修正判断，不能仅按送入模型的字数减少量评价。

## 六 五个目标分别怎样检查

以下五项来自作者明确的目标。表中的检查办法是为落实这些目标提出的候选方法，不是新批准的架构、冻结实验计划或已设定的通过阈值。

| 目标 | 应记录的具体差异 | 需要避免的误判 |
|---|---|---|
| **准确性** | 在什么条件下答对／答错；人物、时间、版本、数量、因果和例外是否区分；结论实际依赖哪段来源；原文完整但选择错误的案例。 | 把原文已保存、引用存在或语言流畅直接当成答案正确。 |
| **可靠性** | 重复运行、状态切换、中断接续、来源缺失和冲突时的行为；是否重复执行、漏接结果或将未知写成成功；不同题型和版本的波动。 | 用单次成功替代持续可靠，或用单个组件测试代表整套系统。 |
| **不被随意污染** | 错误简介、过时内容、来源混淆、伪造指令或无依据推断是否进入可信判断；新记录是否越过允许范围改写旧记录或全局认识；能否追溯并修订。 | 把追加写入当成所有新增内容都可信，或把带哈希的内容当成已核实事实。需要同时检查源记录、索引、当前上下文和最终结论。 |
| **速度** | 定位、预览、展开、核验与回答分别耗时多少；调用次数、读取量、存储和资源代价；首次与重复使用、常见与困难案例的差异。 | 为缩短时间省略必要原文，再把缺证据回答记为更高效率。尾部慢例和失败耗时也应保留。 |
| **诚实保留未知** | 资料缺失、查询未命中、材料冲突、模型不确定和预算不足时是否作出恰当说明；是否编造；有充分依据时是否仍错误拒答。 | 仅统计拒答数。全部说“不知道”并不达成目标；应检查知道与不知道的边界是否正确。 |

目标不是让系统语气上显得谨慎，而是让不知道的内容确实保持不知道，并说明当前缺少什么依据。模型声称自信或不确定，只是待检查的输出，不能自证知识状态。

## 七 评价以差异为主体

作者明确要求重视差异，避免单一分数抹去系统的不同表现。数字可以用于描述某个维度，但不能由一个总分替代解释：哪类题改善了，哪类退步了，为什么，付出了什么成本，还有哪些不知道。

例如，同样的总体正确率可能分别来自“能正确保留未知，但相关材料召回不足”和“召回较多，却将错误简介当事实”。两者的下一步工程行动完全不同。一次更快的回答若丢失例外条件，也不能在加权总分里悄悄抵消。

建议每次比较至少留下：

1. **比较条件：** 版本、底层模型、任务、已有经历、材料、可见信息、预算、运行环境和重复次数。
2. **逐维变化：** 五项目标各自的改善、退步、无明显变化及尚未检查之处；必要时报告分布和不确定性。
3. **案例轨迹：** 入口索引、简介、实际展开的原文、关键判断、错误或未知的具体位置。若公开报告，只使用已允许公开的合成或去标识材料。
4. **原因区分：** 原文采集／保存、检索、语境组织、解释推导、写入与恢复分别检查。未排除替代解释时，不强行归因。
5. **结论范围和下一步：** 本次改变解决了什么，牺牲了什么，下一项验证如何区分竞争解释。失败及原判据保留，后续解释另记版本。

只看总分会让尝试变成盲目提分；保留差异可以帮助定位究竟应修索引、补上下文、调整模型使用方式，还是改善来源与状态约束。它也允许结论是“在这个维度更好，在另一个维度更差”，而不先强迫所有结果排成一个名次。

## 八 怎样借鉴和比较传统方案

现有检索、摘要、长上下文、缓存、版本控制、来源跟踪和评估方法都可以借鉴。借鉴之前应说明它解决哪个问题、依赖什么前提、是否符合本项目原文保留与证据边界要求，再决定采用哪一部分。

比较方法同样需要解释适用性。排行榜、静态任务准确率、压缩率或吞吐量可以回答局部问题，不能未经思考就成为本项目的全部成功标准。反过来，采用项目自己的目标也不能免除基线、反例、泄漏和实际成本的检查。

如要比较“孤立段落”“目标原文＋相关索引简介”“按需展开”“扩大原文窗口”或“长上下文整体读取”，应保持可比较的任务与资料，明确是否匹配底层模型、预算、提示和可见信息，并分别报告差异。用摘要替换历史的系统可以作为另一个研究对象，但不能因此将本方案也描述成记忆摘要压缩。这些是可供选择的对照方向，本次没有执行或指定优胜者。

## 九 原文保留和完整保真之间的证据链

至少要分开四层：

- **保存层：** 被接收的原始内容是否完整、版本是否正确、是否能重新读取。
- **检索层：** 相关材料是否能被找到，索引缺口或别名问题是否造成遗漏。
- **局部语境层：** 当前实际提供的材料是否包含必要前提、指代、例外和相互关系。
- **判断层：** 模型或执行机制是否正确使用材料，有没有把推断、简介或旧事实当成当前已证实结论。

前一层成立不自动保证后一层。保留全部原文解决了可以回查来源的重要问题，但不保证一次查询就找到、有限上下文就覆盖、模型就理解正确。若要提出更强的保真结论，必须明确保真的对象、输入边界、允许的变化、可测判据与覆盖范围。

## 十 后续应验证而尚未完成的事项

1. **明确上下索引关系。** 把父子层级、前后相邻和语义关联分别登记，说明本次提供哪些简介及选择依据，避免只用固定前后段数替代完整意图。
2. **连通实际读取策略。** 在来源、版本和资源约束下组合目标原文与相关简介，并按需展开。现有底层能力、工具暴露和实际模型行为分别验证。
3. **检查简介污染与未知边界。** 使用缺条件、过时简介、矛盾来源和不存在答案的案例；同时检查错误肯定与错误拒答。
4. **检验原文往返与长期接续。** 覆盖输入边界、编码、空白、长文、分页、修订和中断；另行检查真实运行与持久性，不借用 double 结果替代。
5. **按维度比较完整轨迹。** 固定可比较条件，既检查材料使用和结果，也检查时延、资源与失败路径；不以事后加权总分掩盖取舍。
6. **区分切片和完整方案。** 检查底层模型已有能力、原文记忆、关系组织和 FSM 分别作出什么贡献；完整架构缺口另列，不因局部成绩改变定义。
