# 事件链：暂停、反射、接着做

[English](EVENT_CHAIN_REFLEX_20261126.en.md) · [原 FSM 说明](FSM_CONTINUITY.md) · [红尘仙公开原型](https://github.com/zhangyinghao977-beep/hongchenxian-prototype)

## 一个日常例子

你想打开浏览器看一个网页，刚打开却被「设为默认浏览器」挡住了。你可以先略过提示，再打开原先想看的网页，不必从头再开一次浏览器。这个例子只解释设计，不是已运行的浏览器实验。

事件链记录 What、Why、How 之间的转换，也让正在执行的任务可以停在一个明确的地方：浏览器开了，网页还没打开。遇到符合已登记条件的干扰，任务暂停，FSM 临时接手，执行约定的条件反射。确认干扰解除后，交还执行权，从原断点继续。触发时不等 LLM 重新判断。如果条件不匹配、结果不能确认，或者需要新的授权，则不能假定处理完毕；交回逻辑判断，必要时询问用户。

这条窄路径不改变[原 FSM 说明](FSM_CONTINUITY.md)中的高危拉闸或特殊情况由逻辑决定是否继续的规则。

## 本地观察：《脑叶公司》第 12 天

一次本地尝试里，界面显示「镇压中」，但这不能证明队伍已经到位。后续尝试把「危险是否已停住」和「队伍是否到位」分开确认，再继续原任务。这说明为什么反射处理后需要看实际状态，而不能只看一个状态标签。两轮不是严格对照，不能把通关归因于单一机制。本页不附原始录像或日志。

## 现在能跑什么，下一步是什么

- **独立 Agent：** [DLC 03](https://github.com/zhangyinghao977-beep/hongchenxian-prototype/tree/main/dlc03) 用合成输入演示事件链、FSM 协议和反射。运行中的状态目前只在进程内演示，不能据此宣称进程崩溃后可以恢复。现阶段由独立的 LLM 做新情况的判断，决定是否登记新的条件反射；FSM 负责执行已登记的规则。
- **阶段 5／经验主义人工智能：** [阶段 5 设计](../projects/hongchenxian/demo/STAGE5.zh.md)要把 LLM 与 Agent 融合，让同一个系统通过自身经历学出可复用的逻辑，再用于行动。研究目标是让事件链承载原先留在 Transformer 黑盒中的逻辑转换；不是移除整个 Transformer，也不是事后从权重里抽取一套现成规则。融合与学习机制尚未实现。
