# Event chains, concrete knowledge and abstract relations: clarification

[中文](EVENT_CHAIN_RELATIONS.md) · [Glossary](GLOSSARY.en.md) · [Flows](ARCHITECTURE_FLOWS.en.md)

Recorded 2026-11-10. Source U-CHAIN-1110: technical paraphrases of author confirmations during November 9–10. These clarify definitions, not new algorithms, experimental results or validation of the complete architecture. Historical experiments and frozen materials remain unchanged.

## 1. Inclusion, not two disconnected theories

**The learning event chain is a subset of the work event chain.** Both are event chains. The earlier formation/use distinction can describe responsibilities, but cannot replace this inclusion relation or imply unrelated systems.

The compromise agent is a slice of the full empiricist architecture. Its event chain does not undertake the full learning integration because that learning cannot be integrated into the existing logic layer it uses. Coverage and integration differ; the underlying concept is shared, without implying identical or completed implementations.

## 2. Memory and relations

In project terminology, **memory is concrete knowledge; relations are abstract knowledge**. The corpora addressed by learning can correspond to event-chain what–what and what–why relations:

- what–what: **key—door**, expressing the relation “a key can open a door.”
- what–why: **condition—key opens door**, relating a condition to the whole event. Do not substitute “choice—justification” for this example.

Which key and door, when an attempt occurred and its result belong to concrete experiential memory. An original occurrence record is not the abstract relation itself. The author tentatively places these relations within EA's abstract-knowledge scope; this qualification is retained.

“Reversible” includes both bidirectional relation lookup and the bidirectional process of relation formation and use. The author considers the former capable of supporting the latter; concrete formation and update mechanisms remain to be established. This definition alone does not supply an implemented reversible algorithm. Reverse lookup neither reverses the event's direction nor removes its conditions.

## 3. Linking CA and EA

CA borrows attention's ability to connect relationships between statements and binds them to the event chain. Compare these illustrative passages:

- A: “A key can open a door. The prerequisite is that the key matches the lock.”
- B: “A key can open a door. A key can be placed on a table.”

A's second statement supplies a condition for the first; B shares “key” but does not supply an opening condition. Fixed symbols help stabilize representation and aim to reduce computation, but co-occurrence does not imply the same relation. After CA connects A's statements, “condition—key opens door” can be reused as an EA abstract relation while retaining the context connecting the statements. Bidirectional lookup alone does not specify CA↔EA learning and feedback.

The project recognizes attention's relational role. The author's “lookup” criticism of feed-forward networks is a scoped analysis, not a universal assertion that every feed-forward network only performs exact table lookup. Lower computation through fixed symbols remains a design objective, not a proven complexity or performance advantage.
